# Capli：需求草案 v0.1

状态：讨论稿，尚未确定实现方案。日期：2026-10-28。

## 1. 产品目标

让 AI Agent 在编写文档时，通过稳定的命令行接口获取真实界面截图，并把截图作为可追溯的文档素材交付给文档编辑工具。

首个完整示例：用户要求 Agent 编写软件使用说明；Agent 找到目标窗口，截图，读取图片确认内容，必要时裁剪或标注，再把图片插入文档并检查最终展示。

## 2. 已确认的要求

- 支持 Windows 和 macOS。
- 面向能调用本地命令行工具的 Agent，提供 CLI。
- 真实使用场景是 Agent 写文档时获取并使用截图。
- 建立 GitHub 仓库，再梳理需求，之后开发。
- 不使用暂定名 snapdoc；用户要求短且好记，项目工作名采用 Capli（Capture + CLI）。
- 用户已确认 GitHub 仓库公开；初始许可证采用 MIT。

此前讨论过桌面 App；在 CLI 定位明确后，桌面端是否只承担权限、预览和设置，需要重新确认。

## 3. 建议的首版范围（待确认）

| 能力 | 建议行为 | 如何验收 |
| --- | --- | --- |
| 环境诊断 | 检查系统、截图权限和图形会话是否可用 | 返回明确状态、错误码及下一步建议 |
| 发现目标 | 枚举可识别窗口及其应用、标题、ID和状态 | Agent 能选择明确目标；结果不完整时如实标记 |
| 截图 | 按窗口 ID 或明确区域保存 PNG | 返回的文件可解码，尺寸有效，来源与请求一致 |
| 结构化输出 | 在 stdout 输出版本化 JSON，日志写 stderr | 自动化调用不需要解析面向人类的文字 |
| 素材元数据 | 返回路径、尺寸、捕获时间、目标信息与坐标约定 | Agent 能记录来源并正确处理缩放 |
| 文档交付 | 返回图片文件信息，可选生成 Markdown 引用 | 引用相对文档目录正确解析，不虚报已插入文档 |

裁剪、缩放、箭头、步骤编号、指定区域实色遮挡作为候选功能，在核心截图稳定后确定顺序。自动识别敏感信息不作为首版可靠性承诺。

## 4. 关键边界（建议）

- 截图成功不等于内容正确：Agent 应读取图片确认目标内容。
- 工具提供图片；Word、飞书等文档插入操作由对应编辑工具负责，除非明确选择开发特定适配器。
- 不假设权限、已登录浏览器会话、最小化窗口、遮挡窗口或跨桌面捕获在各系统上具有相同能力。
- 窗口匹配不唯一时返回候选项；不静默选择第一个。
- 失败不返回看似成功的图片结果；权限缺失、目标失效和图形会话不可用应可区分。
- 仅本地 CLI 不能让远端 Agent 直接访问用户桌面；远程使用需要另行设计本地桥接。
- 原始截图与处理后截图分别保存，避免修改掩盖来源。

## 5. 首版暂不承诺

- 通用鼠标键盘操作和自动完成整套 UI 流程。
- 跨设备远程控制、云端托管或多用户服务。
- 截图工具内置聊天模型或统一智能体平台。
- 所有文档格式的一键写入。
- 大型可视化评测平台。

## 6. 发布与验证方向（待确认）

- 双平台提供安装和调用说明。
- 同一套 CLI 行为和 JSON 契约覆盖两套平台实现。
- 验证多显示器、不同缩放、窗口关闭、权限拒绝、路径含空格或中文等关键场景。
- 在 Windows 与 macOS 分别验证原生截图能力，单个平台通过不代表跨平台完成。
- 配套 Agent 使用说明；是否同时发布 MCP 适配器后续决定。

## 7. 待逐项决定

1. 首个目标是桌面软件、网页，还是两者都需要。
2. 第一种文档格式以及可复现的真实示例。
3. 首版是否需要人工预览或授权托盘。
4. CLI 语言、原生平台实现和分发方式；尚未锁定 Go/Wails。
